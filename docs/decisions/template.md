# ADR template

```markdown
# ADR-XXX: Title

- Status: Proposed
- Date: YYYY-MM-DD
- Owner: A/B/C/D
- Accepted by: (names, date — when status becomes Accepted)
- Related: issue #, PR #, AC-xx

## Context

What problem are we solving? What constraints apply (course requirements, time,
team size, skills, local-run requirement)? What forces pull in different
directions?

## Options considered

### Option 1 — name

- What it is
- Pros
- Cons
- Cost for this team (setup time, learning, conflict surface)

### Option 2 — name

(same structure)

### Option 3 — name (optional)

## Decision

We chose **X**, because …

## Consequences

Positive:

- …

Negative / accepted costs:

- …

What this makes harder later:

- …

## How we will know it was a bad decision

Observable trigger that would make us revisit, e.g. "if two people cannot work in
parallel without conflicts for a week" or "if tests take more than 30 s".

## Evidence

Links to PRs, test runs, issues or measurements that support the decision.
```
