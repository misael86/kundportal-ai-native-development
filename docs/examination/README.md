# Examinationsunderlag

Använd detta som arbetsunderlag för kursens G- och VG-kriterier. Det visar vad teamet faktiskt har dokumenterat, inte att en student automatiskt uppfyller ett betygskriterium. Varje student behöver länka sitt eget spårbara arbete och skriva sin individuella redovisning i Disco.

## Status just nu

| Område | Underlag/status |
|---|---|
| Problem, krav och nedbrytning | [Featuretickets](../features/README.md) och stabila krav-ID:n täcker ärendeflödena. Teamets senaste implementation finns i [PR #25](https://github.com/misael86/kundportal-ai-native-development/pull/25). |
| Testning och verifiering | [Verifieringsplan](./verification-plan.md) redovisar färska API-, webb-, kravtäcknings- och buildresultat samt begränsningar. |
| AI-instruktioner och återanvändbart arbetssätt | [Copilot-instruktioner](../../.github/copilot-instructions.md) och tre skills finns. Individuell användning och nytta måste fortfarande beläggas. |
| Veckovis progression och granskning | Använd [veckostatusmallen](./weekly-status-template.md); registrera faktiska granskningar och resultat. |
| Individuellt G/VG-underlag | Se [kriteriematrisen](./criteria-matrix.md). Flera kriterier kräver personlig evidens som teamdokumentation inte kan ersätta. |
| Beslut och chatsessioner | [Beslutsloggen](./decision-log.md) och [chattexcerpten och sessionsindexet](./conversation-log.md) sparar tillgängliga användarbeslut med spårbara källor. |

## Vid varje feature

1. Följ ticketens krav-ID:n och lägg till tester för **varje** krav.
2. Spara det faktiska testkommandot och resultatet i verifieringsplanen.
3. Notera en AI-rekommendation ni granskade: vad accepterades, ändrades eller avvisades, och varför?
4. Stanna upp och besvara en reflektionsfråga från [assessment-evidence-skillen](../../.github/skills/assessment-evidence/SKILL.md).
5. Spara länkar till PR/commit och eventuell granskning. Gör inga påståenden om kontroller som inte körts.
